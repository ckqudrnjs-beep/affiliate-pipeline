# 지금 방향 (DIRECTION.md) — 모든 자동 작업의 기준

> 이 파일이 **유일한 기준**이다. 다른 문서·예약 작업 지시문·코드 주석과 다르면 **이 파일이 이긴다.**
> 결정이 바뀌면 ① 이 파일을 먼저 고치고 ② 맨 아래 '결정 기록'에 날짜와 BK 말을 남기고 ③ 그다음 코드·다른 문서를 맞춘다.
> 자동 작업(Actions·예약 작업·Claude API 작업)은 일을 시작하기 전에 자기 채널 칸을 읽는다. 이 파일에 없는 형식·채널·일정은 새로 만들지 않는다.
> 최종 갱신: 2026-11-20

## 0. 프로젝트 지침 (항상, 모든 작업)
BK가 정한 상시 규칙. 어떤 작업도 예외 없음. 세부 작업 규칙은 루트 [AGENTS.md](../AGENTS.md).
1. BK에게는 **한국어**로, 짧게, 단계별로, 주소는 전체 URL(https://…)로.
2. **코드·설정 푸시·배포 전에 BK 확인.** 예외는 BK가 미리 승인해 둔 자동 게시 작업(3장 표의 '자동 승인' 표시)뿐.
3. **비밀번호·API 키는 채팅·파일·커밋·로그에 평문 금지.** 키는 BK가 GitHub Secret 에 직접 넣는다. 저장소는 공개(PUBLIC).
4. **공정위 대가성 표기·플랫폼 정책 준수.** 스팸·어뷰징·약관 위반 자동화, 비공식 봇·매크로 금지. 제휴 링크 숨기기(클로킹) 금지.
5. 인스타·스레드·쇼츠에는 판매·특가·제휴 문구와 제휴 링크를 넣지 않는다.
6. 개인사업자 정보는 어디에도 노출하지 않는다.
7. **계획·지침 MD(이 파일, PLAN, AGENTS 등)는 결정·변경이 생기면 지시 없이 그 자리에서 갱신**하고 날짜를 남긴다.
8. 확인 안 된 숫자·정책은 지어내지 않고 "확인 필요"로 표시.

## 4. 수정 → 반영 → 배포 흐름
결정 하나가 들어오면 이 순서로만 움직인다. 순서를 건너뛰면 어긋남이 생긴다.

1. **결정 받기**: BK 말이 스레드에 남는다. 그 영역 **담당 스레드**가 받는다(3장). 다른 영역이면 그 담당 스레드에 알린다(직접 고치지 않음).
2. **기준에 적기**: 이 파일의 해당 칸을 고치고 맨 아래 결정 기록에 날짜 + BK 말 한 줄. 꺼지는 것은 '꺼진 것'에, 기계가 볼 값은 7장 JSON에.
3. **아래로 맞추기**: 세부 규칙 문서 → 코드 → 예약 작업 지시문 순서. **옛 규칙은 지운다**(위에 날짜로 덧칠하지 않음). 예약 작업 지시문은 "DIRECTION 과 ○○.md 를 읽고 따른다" 수준으로 짧게 두고, 세부는 저장소 문서에만 쓴다.
4. **검사**: 테스트 전체(`PYTHONPATH=src python -m unittest discover -s tests`, 여기 `test_direction` 포함) 통과.
5. **BK 확인 → 푸시·PR·병합**: 지침 0-2. 같은 영역 PR 은 한 번에 하나.
6. **반영 확인**: 병합 뒤 다음 실행 결과를 담당 스레드가 한 번 본다. 매일 07:50 정합성 점검(`consistency`)이 어긋나면 텔레그램 한 줄.
7. **사본 맞추기**: 병합 뒤 바뀐 문서를 프로젝트 폴더 plan/ 에 복사(덮어쓰기 전 .bak). 원본은 언제나 저장소 docs/.
