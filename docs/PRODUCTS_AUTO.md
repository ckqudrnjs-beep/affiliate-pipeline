# 상품 자동 등록·정리 규칙 (승인 없이 바로 반영)

BK 결정 2026-11-13: "가이드가 잡히면 알아서 올려줘." 새 알리 상품은 주 2회 예약 작업(Claude)이 이 규칙대로 골라 main에 바로 올린다.
정리(내리기)는 코드가 매일 자동으로 한다. BK가 할 일은 없다. 이상한 상품을 발견하면 BK가 말만 하면 `status: "hidden"`으로 뺀다.

## 1. 후보가 모이는 곳
- 매일 06:30 KST `curate` 워크플로가 `data/candidates/YYYY-MM-DD.json`을 main에 바로 기록한다(사이트에는 안 보임).
- 검색어: `data/curate_keywords.json`의 요일별 검색어 + 고정 검색어(ALI_KEYWORDS). 계절이 바뀌면 요일별 검색어를 고친다.
- 이미 `data/products`에 있는 상품, 같은 상품의 판매자 변형(이름 앞 18글자 같음), 가품·위험 브랜드(curate.imitation_reason)는 후보에서 빠진다.
- 평점 90%↑, 판매 50개↑, 15,000원↑만.

## 2. 등록 순서 (예약 작업: 화·금 10:2x KST)
1. 최근 7일 `data/candidates/*.json`에서 아직 `data/products`에 없는 상품을 모은다.
2. 아래 기준으로 **최대 3개**를 고른다. 맞는 게 없으면 0개도 괜찮다(억지로 채우지 않는다).
3. `data/products/<slug>.json`을 쓴다(아래 필드). 기존 파일 하나를 형식 예시로 본다.
4. `PYTHONPATH=src python -m unittest discover -s tests`와 `PYTHONPATH=src python -m pipeline.site /tmp/site`가 통과하면 그 파일들만 커밋해 main에 푸시한다. 메시지: "상품 자동 추가 <날짜>: <이름들>".

## 3. 고르는 기준
- 사이트 분야(site.CATEGORIES: 청소·겨울 난방·생활조명·가습·주방·IT·생활잡화·자동차·습도·공구)에 들고, 삼촌의 글·계산기와 이어질 수 있는 물건을 먼저.
- 같은 분야가 한 번에 2개를 넘지 않게. 최근 2주 안에 올린 것과 거의 같은 물건(용도·형태)은 뺀다.
- 지금 계절에 맞는 것(11~2월: 난방·가습·차량 겨울용품·연말 선물).
- 수수료가 높아도 아래는 **빼기**: 의약품·건강기능·화장품·식품·유아용(신생아·젖병), 전기 안전이 중요한데 KC 확인이 어려운 220V 열기구(전기요·히터 본체), 무기·칼(주방칼 제외)·성인용품, 실존 브랜드 로고 위조가 의심되는 것, 상품명에 과장 효능(살균 99%, 전자파 0 등)만 있는 것.
- 같은 물건이 사이트에 이미 있으면(다른 판매자) 추가하지 않는다.

## 4. 파일 필드
- slug(영문 소문자-하이픈), category(위 분야 키), name(한국어 25자 안팎, 판매자 광고 문구 빼고 무엇인지만), aliProductId, aliPrice(후보 가격), aliUrl(후보의 promotion_link 그대로), imageUrl(후보 이미지 = 알리 공식 API 사진, 다른 사진 금지), coupangPrice "" (쿠팡은 BK가 링크를 만들어야 해서 자동 등록 안 함), shipDays "10", lifeMonths(소모품 12, 전자기기 24~36), priceDate(오늘), commission, status "active", addedDate(오늘 KST).
- note(판단 글, 60~150자): 무엇인지 + 누구에게 맞는지 + 가격이 어떤지 + 주의점. 후보 데이터(가격·판매량·평점)와 상품명에 있는 사실만. **써 봤다·효과 있다 같은 체험·효능 표현 금지**, "사세요" 권유 금지.
- check(구매 전 확인, 1~3개): 전압·플러그, 호환 기종, 크기, 소모품 가격, KC 여부 등.
- 대가성 표기·[광고]·rel="sponsored"는 사이트 코드가 자동으로 붙인다(지우지 않는다).

## 4-1. 새로 들어온 물건 (BK 2026-11-13)
- 홈에 "새로 들어온 물건" 칸: addedDate 후 14일 동안만 최신순 최대 8개, 상품 카드에 NEW 표시. 14일이 지나면 칸에서만 빠지고 상품은 "모든 물건"에 그대로 남는다(상품을 기간으로 지우지는 않는다: 글 속 링크·가격 기록·판매 기회가 사라지므로).

## 5. 내리는 기준 (코드가 매일 자동)
| 경우 | 처리 | 다시 올림 |
|---|---|---|
| 알리 조회가 3일 연속 안 됨(판매 종료) | `status: ended` | 안 함 |
| 소개 가격보다 30% 이상 오름 | `status: paused` (판단 글 계산이 안 맞음) | 소개가 +15% 안으로 돌아오면 자동 |
| 철 지난 계절 상품(난방·가습: 4~9월) | 목록에서 잠시 빠짐 | 10월에 자동 |
| 브랜드·가품 위험, BK 요청 | `status: hidden` (사람·Claude가) | 안 함 |

- 내린 상품의 주소(p/<slug>.html)는 지우지 않고 "판매가 끝났어요 / 잠시 내렸어요" 안내 페이지로 바꾼다: 제휴 링크 없음, 검색 색인 제외, 같은 분야 상품으로 안내. 글 속 링크가 깨지지 않고 검색엔진에 404가 쌓이지 않는다. (hidden은 안내 페이지도 만들지 않는다.)
- 상품 페이지는 원래 검색 색인 제외(noindex)라 늘거나 줄어도 검색 평가에 영향이 거의 없다. 검색 유입은 글·계산기가 맡는다.

## 6. 개수 관리 (예약 작업이 등록할 때 같이 본다)
- 사이트에 보이는 상품이 **120개를 넘으면**: 새로 올린 개수만큼, 올린 지 90일이 지났고 글에 연결되지 않은(data/articles의 products·본문 링크에 없는) 상품 중 수수료가 낮은 것부터 `status: "ended"`, `endedReason: "정리"`로 내린다.
- 알리 판매 실적(주문 보고서)을 연결하면 "90일 동안 클릭·판매 0" 기준으로 바꾼다(아직 미연결).
