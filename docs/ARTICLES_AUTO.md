# 삼촌의 글 자동 작성 (하루 1편, 승인 없이 바로 반영)

BK 결정 2026-11-10: 하루 1편을 사람 승인 없이 main에 바로 올린다. 대신 아래 규칙과 자동 검사(tests: ArticleDataTest)를 통과해야만 올린다.
2026-11-16: 11/11~11/16 하루 2편으로 늘렸다가 애드센스 심사(자동 글 비중) 때문에 다시 하루 1편으로 되돌림(BK).

## 순서 (예약 작업이 매일 그대로 따른다)
1. `data/article_topics.json`에서 `done:false`인 질문 중 **아래 "글끼리 닮지 않게" 규칙을 지키는 첫 질문**을 고른다(형식은 `format`, `angle`이 있으면 그 각도로). 다 썼으면 기존 글·상품·계산기를 보고 검색 수요가 있는 새 질문을 하나 만든다(기존 글과 겹치지 않게).
2. `data/articles/<slug>.json` 작성. 필드: slug(영문 소문자-하이픈), date(오늘 KST), title, desc(160자 안팎, 답이 들어간 한 문장), keywords, body, products(0~2개, data/products의 slug), status "published".
3. `data/article_topics.json`의 해당 항목을 `done:true`, `slug` 추가.
4. `PYTHONPATH=src python -m pipeline.seo og` 로 새 글 공유 썸네일(static/og/guide-<slug>.png)을 만들고(한글 글꼴 없으면 건너뜀, 기본 썸네일로 대체), `PYTHONPATH=src python -m unittest discover -s tests` 통과 + `PYTHONPATH=src python -m pipeline.site /tmp/site` 성공 확인 후 main에 커밋·푸시. 실패하면 고쳐서 다시, 그래도 안 되면 올리지 않는다.


## 글끼리 닮지 않게 (BK 2026-11-20, 애드센스 심사 중)
11/10~11/20 글 16편을 재 보니 난방·전기요금 7편, 직구 세금 4편으로 몰렸고, 첫 소제목 8편이 "결론부터/먼저 답부터"로 시작, 14편에 "저도 처음엔", 거의 모든 글이 "결국 ~"과 계산기 안내로 끝났다. 앞으로는:
- **주제 묶음:** 난방·전기요금 / 직구·관세 / 자동차 / 여행·캠핑 / 살림·정리 / IT·충전 중 **최근 2편과 다른 묶음**을 고른다. 한 묶음은 7일에 2편까지.
- **기존 글과 겹치는지 먼저 확인:** `data/articles/`에 같은 질문에 답한 글이 있으면 쓰지 않고 다음 질문으로. 비슷한 글이 있으면 요금표·계산을 다시 쓰지 말고 그 글로 링크하고 **다른 각도**(안전·관리·상황별 시간표 등)만 쓴다.
- **도입 돌려 쓰기:** 첫 소제목은 아래 중 최근 3편과 다른 것. ① 숫자 답 ② 흔한 오해 바로잡기("~라는 말, 반은 맞아요") ③ 상황 장면("아침 7시, 시동이 안 걸릴 때") ④ 독자 질문 한 줄 ⑤ 비교표부터 ⑥ 체크 순서부터. "결론부터/먼저 답부터/먼저 결론/요금만 보면"은 최근 3편 안에 다시 쓰지 않는다.
- **말버릇:** "저도 처음엔", "그렇더라고요" 같은 혼잣말은 최근 3편 안에 같은 표현을 다시 쓰지 않는다.
- **구성:** 표는 꼭 필요할 때만(표 없는 글도 괜찮다). 소제목 수는 3~7개로 글마다 다르게.
- **마무리 돌려 쓰기:** "결국 ~이에요" + 계산기 안내로만 끝내지 않는다. 다음 행동 한 가지, 오늘 할 체크 하나, 관련 글 한 줄, 계절 메모 등에서 고른다.
- **아하 한 줄:** 글마다 사이트 데이터(계산기·시세)에서 나온, 다른 글에 없는 숫자 하나를 넣는다.
- **자동 검사:** `tests`의 `ArticleDataTest.test_articles_not_too_similar`가 본문 겹침(4글자 조각 18% 이상), 25자 넘는 같은 문장, 최근 3편과 같은 첫 소제목 시작·말버릇을 잡는다. 걸리면 고쳐서 다시, 안 되면 올리지 않는다.
- 기존 글은 **주소(slug) 그대로** 두고 내용만 보강한다(삭제·noindex 하지 않음). 보강하면 `"updated": "YYYY-MM-DD"`를 넣는다. 2026-11-20 보강: hot-water-mat-vs-electric-mat-bill(요금표 중복 제거, 사용 비율 각도), ali-black-friday-checklist(같은 문장 1개).

## 사람이 쓴 것처럼 (BK 2026-11-10)
글마다 `data/article_topics.json`의 `format`을 따른다. 같은 형식이 이틀 연속 나오지 않게 한다.

| 형식 | 이렇게 쓴다 |
|---|---|
| 정보 | 검색 질문에 첫 문단에서 바로 답하고 계산·표로 뒷받침 |
| 비교 | 두세 가지를 같은 기준(돈·시간·수고)으로 나란히, 상황별로 "이럴 땐 이것" |
| 체크리스트 | 짧은 도입 + 체크 목록, 항목마다 왜 필요한지 한 줄 |
| 일기 | "삼촌의 일기" 말투. 오늘 든 생각·장면에서 시작해 계산·팁으로 이어짐 |
| 여행 | 여행·나들이 준비 메모. 일정·짐·전기·안전을 실제로 챙기듯 정리 |
| 질문 답장 | 독자가 물을 법한 질문 한 줄로 시작, 삼촌이 답장하듯 |

**말투:** 돈 줍는 삼촌. 친근한 ~해요체, 가끔 혼잣말(그렇더라고요, 저도 처음엔 몰랐어요). 문단 길이를 섞고, 숫자는 꼭 필요할 때만. "결론적으로", "다양한", "~하는 것이 중요합니다", "알아보겠습니다", "도움이 되셨길" 같은 기계적 표현과 매번 같은 틀(서론-본론-결론)은 피한다. 소제목도 질문형·말하듯 다양하게.

**지어내지 않기 (공정위·표시광고법):** 삼촌이 특정 상품을 직접 사서 써 봤다, 실제로 어디를 다녀왔다처럼 사실이 아닌 체험을 쓰지 않는다(가짜 후기에 해당). 일기·여행 글은 생각·계획·준비·계산·일반적인 상황("이럴 때 이렇더라고요"는 널리 알려진 내용만)으로 쓰고, 상품은 "이런 걸 고를 땐 ○○를 보세요" 수준으로 소개한다. 사용 후기·별점·효과 체감 표현 금지. 독자 질문은 "이런 질문을 자주 받아요"처럼 특정인 실화로 꾸미지 않는다. 일기 글도 삼촌에게 실제로 있었던 장면처럼 쓰지 않는다("일요일 밤 장바구니가 23만 원이 돼 있더라고요" ✗ → "예를 들어 장바구니가 23만 원이라면" ○). 날짜·계절·고지서가 오는 시기 같은 일반적인 상황은 써도 된다(2026-11-16 BK).

## 글 규칙
- 주제는 블로그처럼 다양하게: 살림·난방·전기요금·직구·자동차·캠핑·IT·정리 등. 목적은 검색 유입 + 글 안에서 자연스러운 상품 소개. 같은 분야가 3일 연속 이어지지 않게 섞는다.
- 상품 소개: 본문에서 관련 상품을 사이트 상품 페이지 링크(`[이름](p/<slug>.html)`)로 1~3번 자연스럽게 언급할 수 있다(상품 페이지에 [광고] 표기와 계산이 있음). 글 끝 카드는 products 0~2개.
- 검색 질문에 바로 답한다. 첫 소제목에 결론(숫자)을 쓴다. 본문의 80% 이상은 답·계산·비교표.
- 숫자는 근거가 있어야 한다: 전기요금은 사이트 계산기와 같은 기준(src/pipeline/calcs.py의 bill(): 200/400kWh 누진, 120.0/214.6/307.3원, 기본 910/1,600/7,300원, 기후 9원·연료 5원/kWh, 부가세 10%, 기금 2.7%)으로 직접 계산한다. 관세는 목록통관 150달러(미국 200달러), 관세 8%·부가세 10% 기본. 모르는 수치는 지어내지 말고 "제품마다 다름, ○○에서 확인"으로 쓴다.
- **가정 계산은 가정이라고 쓴다 (2026-11-27 정책 검사):** 직접 정한 시간 배분·소비전력(예: 강풍 4시간+수면 20시간)으로 낸 숫자를 "자동 모드면 ○원"처럼 특정 모드·제품의 실제 결과로 쓰지 않는다. 제목·desc에는 가정 조건을 그대로 적고("강풍 4시간·수면 20시간이면"), 본문에 "가정한 계산"이라고 밝힌다. 효율·단가·연비처럼 계산에 넣은 가정도 마찬가지다(2026-11-28 장거리 운전 글: 제목 "점프스타터 완충 전기값 약 22원"이 효율 85%·kWh당 258원 가정을 숨김). **제목에 금액을 넣으려면 "○○이면 약 ○원"·"○○ 가정"·"○○ 기준"처럼 조건을 같이 적고, 조건이 길면 제목에서 숫자를 빼고 본문 표에서 보여 준다.** 자동 검사(articles.validate, 11/28 이후 글)가 조건 없는 제목 금액을 막는다.
- **기기 동작 주장은 출처 있거나 완곡하게:** "센서가 ○○를 먼지로 읽어 강풍이 된다", "2m 띄우세요"처럼 기기 동작이나 정해진 거리·시간을 단정하지 않는다. 제조사 설명서 같은 근거가 없으면 "~할 수 있어요, 거리는 설명서의 설치 안내를 따르세요"처럼 쓴다.
- 본문 형식: `## 소제목`(2개 이상), `- 목록`, `| 표 |`, `**굵게**`, `[글자](calc/electric.html)` 같은 사이트 안 링크만. 외부 링크·제휴 링크는 본문에 넣지 않는다.
- 본문 600자 이상, 목표 2,500~3,500자(2026-11-24 애드센스 "가치가 별로 없는 콘텐츠" 거절 후 상향). 직접 계산한 표나 단계별 예시를 1개 이상 넣고, 같은 말을 늘려 쓰지 말고 상황별 예시·자주 하는 실수·확인 순서처럼 새 정보로 채운다. 한국어, 친근한 존댓말(~해요), 과장 금지(articles.BANNED).
- 상품은 글 내용과 직접 관련 있을 때만 0~2개. 상품 카드는 글 끝에 [광고] 문구와 함께 자동으로 붙는다. 본문에서 "사세요" 식 권유 금지.
- 의약품·식품·화장품·건강 효능 주장 금지.
