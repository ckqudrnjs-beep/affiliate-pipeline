# 애드센스 심사관 점검 2026-11-22 (Claude API 자동)

## 한 줄 판정
**지금 신청하면 'Low value content'로 거절될 가능성이 높습니다.** 계산기, 가이드 글, 원가 레시피는 승인 수준입니다. 그러나 전체 181페이지 중 상당수로 보이는 `news/drop-*`와 `p/*`는 두세 문장짜리 자동 생성형 제휴 페이지라서, 사이트 전체가 얇은 제휴 사이트로 평가될 위험이 있습니다.

---

## 바로 고칠 것

### 1. `news/drop-*.html` 가격 하락 소식 페이지: 개별 페이지를 없애고 한 페이지로 합치기
- **문제**: 각 페이지의 본문이 "알리 가격이 A원에서 B원으로 내렸어요. 판매 페이지에서 확인하세요." 두 문장뿐입니다. 상품명과 숫자만 바뀐 같은 틀이 반복됩니다(이어폰, 커피 저울, 제습기, 공기주입기). 심사에서 가장 먼저 걸리는 '자동 생성, 얇은 페이지, 비슷한 글 반복' 유형입니다.
- **고치는 방법**
  - 개별 drop 페이지를 삭제하고, 각각 해당 상품의 `p/*.html`로 301 리다이렉트합니다.
  - 소식은 `news.html` 한 페이지(또는 월별 1페이지)에 목록으로만 보여 줍니다.
  - 리다이렉트가 어렵다면 최소한 `noindex` 처리하고 sitemap에서 빼세요.
  - 가격 변동 이력은 상품 페이지의 '가격 기록' 안에 넣으면 정보 손실이 없습니다.

### 2. `p/*.html` 상품 페이지: 고유한 내용을 채우거나, 채우기 전까지 `noindex`
- **문제**: 모든 상품 페이지가 같은 틀입니다(지금 살까 판정 → 최저가 → "N개월 쓰면 한 달에 X원" → 2~3문장 소개 → 구매 전 확인 → 제휴 버튼). 사람이 쓴 고유한 내용이 3문장 안팎이고, 나머지는 자동 계산과 고정 문구입니다. 'N개월'도 근거 없이 상품마다 다르게 들어가 있습니다(드립 포트 60개월, 이어폰 24개월, 라이트 바 36개월).
- **고치는 방법**
  - 페이지마다 최소한 다음 내용을 직접 써서 넣습니다.
    - 왜 이 물건을 골랐는지(비교한 대안과 탈락 이유)
    - 사이트 계산기와 연결된 실제 비용 계산(예: 드립 포트 소비전력 × 하루 사용 시간 → 월 전기요금)
    - 사용 개월 수를 그렇게 잡은 이유 한 줄
  - 이렇게 보강하지 못한 상품 페이지는 `noindex`로 두고, 보강한 페이지부터 색인을 엽니다.

### 4. `index.html`의 자동 생성 흔적 지우기
- **원자료 라벨 노출**: "열무/열무가 47% 올랐어요", "사과/시나노골드는…"처럼 KAMIS 품목/품종 라벨이 그대로 보입니다. 품목과 품종이 같으면 하나만 쓰고, 다르면 "사과(시나노골드)"처럼 사람이 읽기 좋은 형태로 바꾸세요.
- **로딩 문구가 본문으로 노출**: "오늘의 얼마게를 불러오는 중이에요."가 그대로 보입니다. 크롤러와 심사자에게 빈 영역으로 보이므로, 오늘 문제를 서버에서 미리 렌더링하거나 `noscript`에 어제 문제와 정답을 넣어 두세요.
- **지난 행사가 '다가오는 세일'에 표시됨**: 11월 22일 기준으로 지난 "11/11 알리 11.11"이 남아 있습니다. 날짜가 지난 항목은 자동으로 빠지게 하세요.

### 5. 광고·제휴 표기와 개인정보처리방침을 실제와 맞추기
- **`recipe/*.html`**: 상단 고지에 "알리익스프레스 어필리에이트 링크도 포함"이라고 되어 있지만 실제로는 쿠팡 링크만 있습니다. 페이지에 실제로 있는 제휴사만 표기하도록 고지 문구를 페이지별로 만드세요. 표기를 줄이라는 뜻이 아니라 정확하게 하라는 뜻입니다.
- **`privacy.html`**: 텔레그램 가격 알림을 운영하므로 구독자의 텔레그램 식별자(chat ID)를 저장하는지, 언제 삭제하는지, 구독을 어떻게 해지하는지 항목을 추가하세요. 지금은 "개인정보를 직접 수집하지 않습니다"라고만 되어 있어 알림 기능과 맞지 않을 수 있습니다.

## 나중에

1. **`guide.html` 주제 겹침 정리**
   - 150달러 관세를 다루는 글이 5편입니다(관세 150달러 기준, 부가세 계산법, 합배송, 장바구니 일기, 블프 체크리스트).
   - 소비전력이 같으면 요금도 같다는 결론의 글이 3편입니다(전기요 vs 전기장판, 온수매트 vs 전기장판, 히터 비교).
   - 주제마다 대표 글 하나를 기준으로 삼고, 나머지는 사례나 체크리스트처럼 역할이 겹치지 않게 다시 쓰거나 대표 글에 합치세요.
2. **`q/*.html` 템플릿 손질**
   - '같이 보면 좋은 글'이 엉뚱하게 연결됩니다(제습기 페이지 → 보조배터리 일기). 같은 범주에서 고르도록 규칙을 바꾸세요.
   - FAQ의 "아래 계산기에서"는 실제로 위에 있는 계산기를 가리킵니다. "위 계산기에서"로 고치세요.
3. **레시피 기준가 날짜 통일**: 제육볶음은 2026-11-13, 로제 떡볶이와 `recipe.html`은 11-14입니다. 기준가 표를 바꾸면 각 레시피의 기준 날짜와 원가도 함께 다시 계산되게 해 두세요.

## 좋은 점

1. **정책 페이지가 구체적이고 정직합니다.** 개인정보처리방침은 AdSense와 카카오 애드핏의 쿠키, 맞춤 광고 해제 경로, Cloudflare 통계, IP 해시 처리까지 실제 동작대로 적었습니다. 문의 페이지에는 이메일과 답장 기간, 소개 페이지에는 출처·수정 원칙과 "써 보지 않은 물건을 써 본 것처럼 쓰지 않는다"는 원칙이 있습니다. 제휴 표기도 상단, 버튼 앞, 푸터에 일관되게 붙어 있습니다.
2. **검증 가능한 고유 가치가 있습니다.** 오피넷·KAMIS·ECOS 같은 공공 데이터에 출처와 날짜를 붙였고, 누진제를 반영한 계산기가 있습니다. 레시피 원가표는 기준가와 사용량으로 다시 계산하면 합계가 정확히 맞습니다(제육볶음 3,140원, 로제 떡볶이 7,940원). 이런 페이지들이 심사에서 이 사이트를 살릴 핵심이므로, 1~2번을 정리해 이 페이지들이 사이트 전체에서 차지하는 비중을 높이는 것이 승인으로 가는 가장 빠른 길입니다.
