# 5락실 게임 그래픽 품질 기준 (GAME_QUALITY.md)

> 최초 작성 2026-11-14 (BK: "네온 생존자 대비 디자인이 떨어지는 게임 개선, 앞으로 게임도 품질 신경"). 기준 게임 = **네온 생존자**(/games/survivor).
> 새 게임은 PR 올리기 전에 아래 체크리스트(+5장 게임 전용 스킨)를 통과해야 하고, PR 본문에 체크 결과와 휴대폰·PC 스크린샷을 붙인다.

## 1. 필수 체크리스트 (10개 중 9개 이상 = 통과)
1. **첫 화면 포스터**: 페이지에 빈 캔버스·회색 상자 대신 실제 게임 그림 포스터(16:9, `static/img/<slug>-poster.jpg`) + 노란 ▶ 시작 버튼. 공유 이미지(og)도 같은 포스터. 포스터는 손으로 만들지 않고 2-1 자동 캡처로 만든다.
2. **전체 화면 플레이**: 시작하면 전체 화면 오버레이(아이폰은 화면 꽉 찬 오버레이), meta.json `"ownfs": true`. 오른쪽 위 🔊 Ⅱ ✕ 버튼.
3. **배경에 깊이**: 단색 금지. 그라데이션 + 성운/빛 번짐 + 움직이는 2겹 이상(별·입자·격자). 가로 화면 양옆 빈 공간도 꾸밈.
4. **주인공·적·아이템은 코드로 그린 그림**: 이모지·기본 도형(단색 원·사각형)만으로 된 캐릭터 금지. 그라데이션·하이라이트·외곽 빛. 상점 스킨도 같은 품질로 직접 그림.
5. **네온 빛**: 중요한 물체에 빛(glow) — `shadowBlur` 대신 미리 그린 빛 스프라이트 + `lighter` 합성(성능).
6. **손맛(juice)**: 맞힘·획득·죽음마다 입자, 떠오르는 점수 글자, 고리 파동, 화면 흔들림/번쩍임 중 최소 3가지.
7. **소리**: 웹오디오 합성 효과음 4종 이상 + 배경음(끄기 버튼, 설정 기억).
8. **HUD**: 점수·시간·단계를 픽셀 글꼴(Press Start 2P)로, 제목·안내는 Black Han Sans. 처음 3초 조작 안내.
9. **결과 화면**: 점수 크게, NEW BEST, 기록 3칸(시간·수집·특기), 다시 도전(Enter)·결과 공유·이 게임 상점·나가기.
10. **성능·공정성**: 픽셀 비율 최대 2·화면 픽셀 360만 상한, 스프라이트 미리 그림, 고정 프레임(1/60) 업데이트. 경기장 넓이는 기기와 상관없이 같게. 멈춤 한 판 1번 + 3초 카운트다운(자동 멈춤 무료).

## 2. 권장
- 단계가 오르면 배경음 빨라짐·"SPEED UP" 같은 연출.
- 디버그 `#<slug>debug` → `window.__xx` (bot, fast, god, poster) — 쇼츠 녹화·포스터 제작용.
- 포스터는 **자동 캡처**(2026-11-15 BK): 아래 5장.

## 2-1. 포스터 자동 갱신 (2026-11-15 BK: "게임을 고치면 시작 전 포스터도 고친 게임 그림으로")
- 전체 화면 게임(`ownfs`)과 포스터를 쓰는 게임은 meta.json 에 **`"poster"` 조리법**을 꼭 넣는다(테스트 `tests/test_raksil_posters.py` 가 검사):
  `{"hash": "#<slug>debug", "run": "await P.go(); await P.until(()=>window.__xx&&__xx.G()); __xx.god(true); __xx.bot(true);", "wait": 6000, "title": true, "hide": ".선택자"}`
  - `P.go()` 시작 버튼 누르기, `P.until(fn)` 조건 기다리기, `P.sleep(ms)`. 테스터 전용 게임도 찍힌다(찍는 브라우저에서만 테스터로 침).
  - `title: true`(기본) 면 화면 아래에 게임 이름·한 줄 소개 띠를 얹는다. 게임이 직접 제목을 그리면 `false`.
- `python playground/posters.py` : 게임 원본(게임 폴더·`static/js/<slug>*.js`·`static/img/<slug>/`·조리법) 해시가 `static/img/posters.json` 과 다른 게임만 실제 화면을 1280×720 으로 다시 찍어 `static/img/<slug>-poster.jpg` + 공유 이미지 `static/og/<slug>.jpg`(1200×630) 저장. `--all` 전부, `--check` 확인만.
- **자동**: main 에 게임 변경이 들어오면 GitHub Actions `posters` 가 바뀐 게임만 다시 찍어 main 에 커밋 → Cloudflare 재배포. 게임 PR 을 올리는 에이전트는 PR 전에 직접 돌려 새 포스터를 PR 에 같이 넣는 것을 권장(BK가 미리 볼 수 있게).
- **캐시 방지**: build.py 가 게임 본문의 `/img/…`, `/og/…` 그림 주소와 og:image 에 `?v=<내용 해시>` 를 자동으로 붙인다. 손으로 `?v=2` 를 붙이지 않는다.

## 5. 새 게임 = 게임 전용 스킨도 같이 (2026-11-16 BK: "새 게임이 올라오면 스킨도 제작")
새 게임을 올리는 PR 에는 그 게임 전용 꾸미기(스킨)를 **같은 PR** 에 넣는다. 테스트 `tests/test_raksil_skins.py` 가 모든 게임을 검사한다(스킨이 없으면 실패).

**게임 종류별 기준** (기존 게임 관행 그대로):
| 종류 | 예 | 넣을 것 | 개수·가격(🪙) |
|---|---|---|---|
| A. 캐릭터가 움직이는 액션·아케이드 | 별빛·통통·생존자·탑·별사탕 | `DESIGNS` 캐릭터 스킨 + `DESIGN_GAMES` 기본 이름 | 일반 3종 5~6 / 7~8 / 10~12 + **전설 1종 50**(`leg`) = 4종. 권장: 배경 테마 `THEMES` 3종 10/15/20 |
| B. 캐릭터 없는 짧은 게임·퍼즐·하루 문제 | 사격장·별똥별·딱 멈춰·반응속도·숫자 퍼즐·초성·다수결·틀린그림 | `GAME_ITEMS`(종류 1~2가지: 조준점·막대·신호 색·축하 효과 등) | 2~6종, 4~15 |
| C. 게임 안 화폐가 있는 RPG | 네온 레이드·몽글숲 | 게임 안 화폐로 사는 꾸미기 + `games/<slug>/items.json`(관리자 지급, 0-7 규칙) | 6종 이상, 게임 안 화폐 |
| D. 도구 | 게이머 면허증 | `GAME_ITEMS` 테두리 등 | 1~2종, 4~8 |

**지켜야 할 것**
- 꾸미기는 **겉모습만**: 점수·판정·능력 영향 없음. 화려할수록 비싸게.
- 그림은 1장 4번처럼 **코드로 직접 그린 그림**(이모지 아이콘은 상점 표시용만). 스킨마다 특수 효과(점프·필살기 순간 빛 등)가 있으면 더 좋음.
- 코인은 출석·미션·업적·공유로만 무료로 생긴다. **현금 판매·거래·선물·뽑기(가챠)·랜덤 상자 금지**, 광고 시청과 연결 금지.
- 게임 화면의 `🛒 이 게임 상점`(build.py 자동, 위 목록에 slug 가 있으면 생김)과 /bonus '게임별 꾸미기'에 나오는지 확인.
- 고른 스킨이 게임 시작·이어하기·결과 화면·포스터 캡처에서 깨지지 않는지 확인(포스터는 기본 스킨으로 찍힘).
- 업적 코인이 필요하면 `ACH` 에 게임 업적 1개(🪙3) 추가 권장.

**스크린샷**: 휴대폰 화면으로 ① 이 게임 상점(스킨 목록) ② 스킨을 낀 플레이 화면 2장 이상을 `/mnt/project-files/5raksil-<slug>/` 에 저장하고 PR 본문·BK 보고에 붙인다.

**예외**: 스킨이 어울리지 않는 게임(예: 글만 있는 페이지)은 BK 확인을 받은 뒤 meta.json 에 `"noskin": "이유"`. 확인 전 임시 표시는 `"noskin": "BK 결정 대기(날짜)…"` 이고, BK 답이 오면 지운다.

**스킨 점검 (2026-11-16)**: 스킨이 없던 네온 올가미(올가미 선 3 + 잡을 때 효과 2)·끊어진 하늘(발밑 오라 3 + 걸음 흔적 2, 모든 직업 공통 코인 상점 — 게임 안 골드 상점과 별개)에 BK 승인으로 추가 → 이제 모든 게임에 스킨 있음. 스크린샷 `/mnt/project-files/5raksil-skins/`.
