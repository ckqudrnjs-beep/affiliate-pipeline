## BK가 콘솔에서 직접 확인할 것 (5분)
1. **Billing → Credits**: 남은 금액 확인(만료 2026-12-14는 메일로 확인됨).
2. **카드는 등록하지 않는다**(크레딧만으로 사용 가능). 나중에 카드를 넣게 되면 Limits → Spend limit을 100달러로 걸어 월 예산 5만원 규칙을 지킨다.
3. **API Keys → 새 키 만들기** (이름 예: `github-actions`). 키는 채팅·파일에 붙이지 말고 **GitHub 저장소 Settings → Secrets and variables → Actions → `ANTHROPIC_API_KEY`** 에 BK가 직접 넣는다. (저장소가 공개라 절대 파일에 쓰지 않음)
   - 넣으면 `api-check.yml`(하루 4번)이 키가 살아 있는지 자동 점검하고, 문제 있으면 텔레그램으로 알려 준다(이미 만들어 둠).

## 지금 구조와 크레딧이 들어갈 자리
- 지금 글·쇼츠 대본 같은 "글쓰기"는 대부분 **Claude 예약 작업(BK 구독 요금제)** 이 한다. 돈은 안 들지만 구독 사용량 한도를 같이 쓰고, 한도에 걸리면 그날 작업이 빠질 수 있다.

## 매달 쓰는 곳 (매 회차 기본, 수익에 가까운 순)

### 1. 동전이 쇼츠 대본 "여러 안 + 채점" (Opus 5.5)
- 이틀에 1편 대본을 만들 때 훅·대본을 5~8안 쓰고, 별도 호출이 세계관 바이블·아하 규칙·첫 1초 훅 기준으로 채점해 상위 2안만 남긴다. BK는 고르기만.
- 왜: "1편 품질이 사이트 운명 좌우"(BK 11/19). 쇼츠는 지금 가장 큰 유입 통로.
- 비용: 1회 입력 2만·출력 1만 토큰 ≈ $0.28 → 월 15회 ≈ **$4~5**.

### 2. don3chon 기존 글 품질 손질 (Sonnet 5.5 + Batch)
- 색인된 글 ~100편을 하나씩: 첫 문단에 바로 답이 있는지, 숫자·출처가 사이트 데이터와 맞는지, 기계적 표현("결론적으로" 등), 얇은 부분을 찾아 **고친 안을 PR로** 올린다(자동 반영 아님, BK 확인 후).
- 왜: 애드센스 심사 중이라 "새 글 늘리기"보다 "있는 글 질 올리기"가 안전하고 승인·검색 순위에 직접 도움.
- 비용: 글당 입력 8천·출력 4천 토큰, 배치 50% ≈ $0.03 → 100편 한 바퀴 ≈ **$3**. 매달 한 바퀴 돌려도 충분.

### 3. 자동 글·쇼츠 올리기 전 "검사관" (Haiku 5.5)
- 매일 05:00 자동 글, 쇼츠 문구가 main에 올라가기 전에 GitHub Actions에서 한 번 더 검사: [광고] 표기 누락, IG/쇼츠/스레드에 제휴 링크·판매 문구, 개인사업자 정보 노출, 금지 표현, 사실과 다른 숫자. 걸리면 올리지 않고 텔레그램 알림.
- 왜: 공정위 표기·플랫폼 정책 위반 한 번이 채널·애드센스를 날릴 수 있음. 사람 손 안 대는 구조(BK 11/17)에 맞는 안전장치.
- 비용: 1회 ≈ $0.002 → 월 100회 넘어도 **$1 미만**.

### 합계와 여유
- 위 3가지 ≈ **월 $10 안팎**. 100달러의 10% 정도.
- 남는 크레딧 후보(우선순위 순, 하나씩 BK 확인 후):
  - 매일 자동 글을 예약 작업 대신 Actions + Opus 5.5로 옮겨 안정화 (월 ≈ $8). 애드센스 승인 후 하루 2편으로 늘릴 때 같이.
  - 월요일 KAMIS·오피넷 데이터에서 "아하 한 줄" 뽑기 → 장보기 카드·쇼츠 소재 (월 ≈ $1).
  - 5락실 게임 공략·영어 설명(Broken Sky EN 등) 손질 (한 번에 ≈ $2).
- 이 정도면 월 $20~25 수준이라 100달러 안에서 넉넉하다. 크레딧이 끊겨도 각 작업은 예약 작업 경로로 되돌릴 수 있게 만든다(지금 shorts.py처럼 "키 있으면 API, 없으면 기존 방식").

## 비용 줄이기: 캐싱·배치·어드바이저 (2026-11-20 검토, BK가 공식 문서 3개 공유)

크레딧은 회차마다 공짜 100달러(이월 없음)라 아끼면 현금이 남는 게 아니라 **같은 돈으로 더 많이·덜 막히게** 된다.
제일 급한 곳은 toon(회차 상한 15달러): 11/20 첫날 2번 돌아 1.93달러, 한 번 ≈ 0.95달러(입력 ≈ 0.2, 출력 ≈ 0.75) → 격일이면 상한에 거의 닿는다.

| 방법 | 할인 | 우리 쪽 효과 | 결정 |
|---|---|---|---|
| 프롬프트 캐싱 | 읽기 0.05배(Opus·Sonnet 5.5), 쓰기 1.25배(5분)/2배(1시간) | 입력만 줄어든다. toon 한 번 약 3~8%(0.03~0.08달러), polish 약 2% | **적용** (아래) |
| 배치(Message Batches) | 입·출력 모두 50% | toon 한 번 ≈ 0.47달러 절약(월 ≈ 7달러). 주간 작업도 반값. 대부분 1시간 안, 최대 24시간 | **적용** (BK 11/20 "배치도 진행") |
| 어드바이저(베타) | Sonnet 실행 + Opus 조언 | 대본 생성 출력값 절반쯤(한 번 ≈ 0.2달러). 단, 한 번에 끝나는 호출엔 덜 맞는다고 문서에 적힘 + 품질 미검증 | 보류 (품질 우선) |

캐싱 적용 규칙 (`claude_jobs.ask(cache=...)`)
- 같은 system 을 몇 분 안에 다시 부르는 곳만 켠다: toon 작가·다듬기(1시간 — 출력 2만 토큰 생성 + 채점 뒤라 5분을 넘기 쉬움), 채점·재채점(5분), Veo 프롬프트 2번(5분), polish 글 여러 편(5분).
- 사이트 근거(site_facts)는 user 끝 → system 끝으로 옮겨 캐시에 같이 들어가게 했다.
- 끄는 곳: adsense·titles·shorts·naver·check(주 1회·하루 1회 한 번 호출 → 쓰기 값만 더 냄), raksil(system ≈ 380토큰 < 최소 512), early(하루 3번, 몇 시간 간격 → 5분·1시간 모두 만료).
- 같은 캐시를 쓰려면 effort·모델이 같아야 한다(작가·다듬기 high, 채점·재채점 medium 으로 맞춰 둠).
- 장부(data/api_usage)에 `cache`(읽기)·`cache_w`(쓰기) 토큰이 남는다. 0·0 이면 캐시가 안 된 것.

배치 적용 규칙 (`claude_jobs.BATCH_JOBS`)
- 배치: toon·adsense·shorts·titles·polish. 일반 호출: raksil·early(공개 시각에 맞춰야 함), check(하루 몇 센트), naver(직접 돌림).
- 호출마다 요청 1개짜리 배치를 넣고 20초마다 확인. 45분 안에 안 끝나면 취소하고 일반 호출, 작업 시작 150분 뒤부터는 남은 호출 모두 일반 호출(워크플로 제한 240분).
- 배치에선 `fallbacks`(거절 시 다른 모델 재시도)를 못 쓴다 → 거절이면 fallbacks 있는 일반 호출로 한 번 더(거절 값도 장부에 남김).
- 배치에선 캐시를 1시간으로 쓴다(5분은 다음 단계 전에 만료되기 쉬움, 문서 권장).
- 장부에 `"batch": true` 와 반값이 남는다. 끄려면 실행 환경에 `CLAUDE_BATCH=0`을 넣는다.
- 워크플로는 작업마다 따로 줄을 선다(`claude-jobs-<일정>`): toon 이 길어져도 월요일 shorts·titles 가 밀려 취소되지 않게.
- toon 후보는 공개 약 12일 전에 만들어서 몇 시간 늦어도 괜찮다.
