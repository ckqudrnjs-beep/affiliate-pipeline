# 5락실 공략·가이드 글 (RAKSIL_GUIDES.md)

> 최초 작성 2026-11-16 (BK: "신규 게임은 몇 개 더? 각 게임별 플레이 가이드·공략으로 애드센스 승인 앞당기게 세팅"). 사본: /mnt/project-files/plan/RAKSIL_GUIDES.md

## 1. 결론: 게임 수보다 글 깊이
- 애드센스 심사는 "글로 된 고유한 내용이 충분한가"를 본다. 게임 화면은 캔버스·자바스크립트라 심사 로봇에게 거의 빈 페이지로 보인다. 게임을 더 올려도 승인 확률은 거의 안 오른다.
- **새 게임은 승인용으로는 0개 더 필요**(16개면 충분). 대신 게임마다 공략 글 1개 + 공통 안내 글 몇 개 = 글 페이지 20~25개를 목표로 한다.
- 2026-11-16 기준 색인 대상 페이지 24개(게임 16 + 소개·약관 등) → 1차 공략 8개 + 허브 1개로 33개.

## 2. 구조 (코드: playground/build.py `load_guides`, 글: playground/guides/<slug>.md)
- `/guide` 허브: 장르별(액션·퍼즐·타이밍) 카드 + 공통 안내 글 묶음. 메뉴 '공략'(작은 휴대폰에서는 밸런스·순위가 아이콘 ⚖️🏆 으로 줄어듦).
- `/guide/<slug>`: 제목·업데이트 날짜·요약·게임 바로가기·목차·본문(광고는 세 번째 소제목 앞 1곳)·다른 공략. Article + 빵부스러기 JSON-LD, 사이트맵 자동.
- 게임 페이지 규칙 아래 '📖 공략' 카드, 홈에 최신 공략 4개, 소개 페이지에 공략 링크.
- 글 형식: 앞머리 `title / description / game(선택, 게임 폴더 이름) / updated` + 마크다운 일부(`##`, `###`, `-`, `1.`, `> 팁`, `| 표 |`, `**굵게**`, `[링크](/경로)`). HTML 직접 쓰기 금지(이스케이프됨).

## 3. 글 쓰는 규칙 (빌드가 일부 자동 검사)
1. **숫자는 게임 코드에서 확인한 것만**: 점수 공식, 속도 변화, 판정 폭, 단계 표. 추측 수치 금지. 게임 규칙을 바꾸는 PR은 해당 공략 글도 같이 고친다(`updated` 갱신).
2. **해 본 척 금지**: "제가 해 보니 3천 점" 같은 지어낸 경험 쓰지 않는다. 운영자가 만든 게임의 실제 규칙 설명 + 요령.
3. **틀 복사 금지**: 게임마다 소제목·구성이 달라야 한다. 빌드 검사 — 본문 1,800자 이상, 소제목(##) 4개 이상, 다른 글과 5글자 조각 겹침 25% 이하(넘으면 빌드 실패).
4. 들어가면 좋은 것: 숫자 표 1개 이상, 처음 하는 분 → 순위권 단계, 흔한 실수, 자주 묻는 질문 2~3개.
5. 다른 회사 게임 이름·캐릭터 비교 금지, 과장 금지("무조건", "100% 1등").
